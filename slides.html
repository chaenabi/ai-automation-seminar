    기대와 다른 결과
    “AI를 통한 자동화”는 새 개념이 아니다.

    그래서 우리는 새 도구의 이름보다, 업무를 제대로 위임하는 원칙을 먼저 기억해야 한다.

    사람과 AI의 공통점

    왜 “새 개념이 아니다”가 중요한가?

    Garbage In, Garbage Out.
    입력값이 쓰레기이면 출력값도 쓰레기다.

    AI는 인간보다 작업 속도가 빠르다.
    다만 사람에게 위임하든 AI에게 위임하든, 목표·맥락·제약·검증 기준이 부실하면 결과도 흔들린다.

    프론티어 모델의 착시

    “개떡같이 말해도 찰떡같이 답하던데요?”

    01

    사전 학습

    엄청난 양의 언어 패턴과 범용 지식을 이미 익혔다.

    02

    숨은 하네스

    시스템 지침, 안전 정책, 도구 규칙, 대화 관리가 서비스에 내장돼 있다.

    03

    일반적 기대

    범용 질문은 평균적인 답만으로도 많은 사용자가 만족한다.

    특수한 업무로 들어가는 순간, 내 조직의 맥락과 규칙을 직접 제공해야 한다.

    HISTORY OF INSTRUCTION

    인간이 기계에게 업무를 지시해 온
    눈물겨운 3단계

    1.0

    코드

    모든 규칙을 사람이 명시한다.

    2.0

    데이터

    예시로 가중치를 학습한다.

    3.0

    자연어

    언어와 컨텍스트로 행동을 지시한다.

    SOFTWARE 1.0

    규칙을 항상 명시

    • 조건, 반복, 순서를 코드로 작성
    • 개발자에게 친숙하지만 일반인에게 어려움
    • 예외가 늘수록 규칙도 폭발
    if (vip) discount = 20;
else if (coupon) discount = 10;
else if (event && firstBuy) ...
else if (...) ...

    명시적 규칙의 끝: else-if 지옥

    SOFTWARE 2.0

    규칙 대신 데이터로 가중치를 학습

    문장 → 토큰 ID

    “오늘 날씨가 좋다”

    오늘ID 3921 날씨ID 8174 가ID 214 좋ID 6508 다ID 105

    실제 ID와 분할 방식은 모델마다 다르다.

    가중치 조정 → 정답 확률 상승

    예측 목표: “오늘 날씨가 좋다”

    초기
    학습 1
    학습 2
    수렴

    정답과 예측의 오차를 계산하고, 오차가 줄어드는 방향으로 가중치를 조금씩 바꾼다.

    SOFTWARE 3.0

    자연어로 행동을 프로그래밍

    누구에게나 친숙하고, 명시 규칙과 학습된 암묵 규칙이 함께 작동한다.

    역할: 당신은 고객지원 담당자입니다.
목표: 환불 요청의 긴급도를 분류하세요.
규칙: 정책 문서에 없는 내용은 추측하지 마세요.
출력: {"등급": "...", "이유": "...", "다음 행동": "..."}
    행동을 바꾸려면 코드를 다시 학습시키는 대신, 컨텍스트를 바꾼다.

    도구가 필요하면 모델은 자연어 의도를 구조화된 호출이나 코드로 변환해 실행 환경에 요청한다.

    NEXT TOKEN PREDICTION

    문맥에 따라 다음 토큰의 확률이 달라진다

    예시 1. “회의가 취소되어서 시간을…”

    확보했다
    72%
    먹었다
    12%
    달렸다
    7%

    예시 2. “뜨거운 냄비를 맨손으로 잡으면…”

    위험하다
    67%
    화상
    21%
    즐겁다
    2%
    AI는 인간처럼 “옳고 그름”을 느끼지 않는다.
    맥락상 가장 그럴듯한 다음 토큰을 계산한다.

    가치 판단처럼 보이는 답변도 학습 데이터, 후속 정렬, 시스템 정책, 현재 컨텍스트의 결과다.

    GENERAL ≠ SPECIFIC

    똑똑해 보여도, 모르는 맥락은 채울 수 없다

    “우리 회사 시스템을 개선해줘”

    아키텍처, 트래픽, 장애 이력, 비용, 규제, 목표가 없다. AI는 일반론만 말하거나 추측한다.

    “살 만한 주식 추천해줘”

    AI는 사용자가 어느 나라 주식을 원하는지, 언제 얼마를 매수할지, 단기·중기·장기 중 얼마나 보유할지, 손실을 얼마나 감수할지 모른다.

    표·보고서·종목 목록 등 원하는 결과 양식도 없으므로, 결국 일반적인 수준의 답만 줄 수 있다.

    모델의 한계만 탓하기 전에, 업무의 정답지를 정의했는지 확인해야 한다.

    CONTEXT

    결국 중요한 것은 “맥락”이다

    한국어를 흔히 고맥락 언어라고 부르지만, 개인·조직·상황 차이가 크다. AI에게는 암묵적 맥락을 기대하지 않는 편이 안전하다.

    한국어 해프닝

    “한번 검토해 주세요.”

    사람 사이에서는 “문제점을 찾아 수정안까지 달라”는 뜻일 수 있다. AI는 요약만 하고 끝낼 수 있다.

    영어 해프닝

    “That might be difficult.”

    완곡한 거절 의도였지만 상대는 “어렵지만 가능”으로 받아들여 계속 진행할 수 있다.

    암묵지를 명시지로 바꾸는 일이 곧 프롬프트 설계다.
    BEFORE / AFTER

    질문이 아니라 업무 명세를 전달한다

    잘못된 질의

    “우리 서비스 장애 원인 분석해줘.”

    대상, 증거, 목표, 제약, 결과 형식이 없다.

    개선된 질의

    역할: 당신은 SRE 리드입니다.

    목표: 09:00~09:20 결제 오류 급증의 가장 유력한 원인 3개를 찾으세요.

    근거: 첨부 로그와 배포 이력만 사용하고, 모르면 “근거 부족”이라고 쓰세요.

    규칙: 각 가설에 근거·반증 방법·위험도를 붙이세요.

    출력: 표 + 즉시 조치 3단계. 감사합니다.

    칭찬과 감사는 대화를 부드럽게 할 수 있지만, 품질을 결정하는 핵심은 역할·목표·맥락·제약·검증 기준이다.

    OUTPUT COMPARISON

    같은 모델, 다른 입력, 다른 결과

    모호한 질문의 답
    장애 원인은 네트워크 문제, 서버 과부하, 데이터베이스 오류 등일 수 있습니다. 로그를 확인하고 모니터링 지표를 살펴보세요.

    그럴듯하지만 바로 행동하기 어렵다.

    명세된 질문의 답
    1순위: 08:57 결제 API v2.14 배포
    근거: 배포 3분 뒤 5xx가 0.4%→18.2% 증가
    반증: 이전 버전으로 5% 카나리 롤백 후 오류율 비교
    위험도: 높음

    즉시 조치: 신규 트래픽 차단 → 카나리 롤백 → 결제 재처리 큐 보존

    근거와 다음 행동을 바로 검증할 수 있다.

    MCP PRACTICAL GUIDE

    MCP는 기능, 연결 방식, 신뢰 경계로 본다

    서버 기능

    • Tools: 실행 가능한 작업
    • Resources: 읽을 컨텍스트
    • Prompts: 재사용 지시 템플릿

    연결 방식

    • stdio: 로컬 프로세스
    • Streamable HTTP: 원격 서버
    • 원격 연결은 인증·TLS·승인 정책 필요

    설정 순서

    • 서버 출처와 코드 검토
    • 클라이언트에 command 또는 URL 등록
    • 최소 권한 환경 변수·경로 설정
    • Inspector로 스키마와 호출 시험
    {
  "mcpServers": {
    "project-files": {
      "command": "npx",
      "args": ["-y", "@example/files-server", "/allowed/project"]
    }
  }
}

    설정 키는 클라이언트마다 다르다. 공식 문서: modelcontextprotocol.io/docs · Inspector: modelcontextprotocol.io/docs/tools
